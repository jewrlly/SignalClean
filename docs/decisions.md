# Лог рішень (проблема → рішення)

### 1. Яку БД обрати, щоб проєкт запускався «з нуля» на будь-якій ОС
**Проблема.** PostgreSQL або SQL Server треба окремо встановлювати чи запускати в Docker. Це ускладнює запуск за README (критерій E3) і показ на кількох ОС.
**Рішення.** SQLite через EF Core: файл БД створюється автоматично під час першого запуску API. Для навчального проєкту з одним сервером цього достатньо. Перехід на PostgreSQL зводиться до зміни провайдера в `Program.cs`.

### 2. SQLite не сортує `DateTimeOffset`
**Проблема.** SQLite-провайдер EF Core не перекладає в SQL `ORDER BY` та порівняння за полями `DateTimeOffset`.
**Рішення.** У сутностях БД час зберігається як `DateTime` в UTC (`TimestampUtc`), а в DTO повертається як `DateTimeOffset`. Конвертацію виконує `IngestService.ToOffset`.

### 3. Як шукати сплески, щоб самі викиди не спотворювали поріг
**Проблема.** Правило «середнє ± 3σ» нестійке: один викид −999 зсуває середнє та роздуває σ, і наступні викиди вже не помічаються.
**Рішення.** Медіана та MAD (σ ≈ 1.4826·MAD) за вікном попередніх **очищених** значень, тобто каузальний варіант фільтра Гампеля. Значення поза фізичним діапазоном відсікаються ще валідатором і в історію не потрапляють.

### 4. Хибні сплески на майже постійному сигналі
**Проблема.** Коли сигнал майже не змінюється, MAD ≈ 0, і будь-яка зміна на 0.1 вважалась сплеском.
**Рішення.** Поріг сплеску дорівнює `max(4σ, 2 % діапазону датчика)` (`ProcessingOptions.MinSpikeFraction`). Це покрито тестом `IsSpike_ConstantHistory_UsesAbsoluteThreshold`.

### 5. Датчик надсилає NaN, і запит падав на десеріалізації
**Проблема.** Стандартний `System.Text.Json` не приймає `NaN` у JSON. Такий запит відхилявся цілком, і дефект датчика не фіксувався.
**Рішення.** `JsonNumberHandling.AllowNamedFloatingPointLiterals` на сервері, у симуляторі та в клієнті. NaN доходить до валідатора і записується як аномалія `NotANumber`.

### 6. Частковий запис пакета при помилці
**Проблема.** Якщо під час запису пакета сталася помилка, частина вимірювань могла зберегтися без своїх аномалій.
**Рішення.** Увесь пакет зберігається в одній транзакції (`BeginTransactionAsync` → `SaveChangesAsync` → `CommitAsync`). Без commit транзакція відкочується під час `Dispose`.

### 7. Графік «сплющувався» через викиди
**Проблема.** Якщо масштаб осі Y рахувати за сирими даними, одне значення −999 стискає реальний сигнал у пряму лінію.
**Рішення.** Масштаб рахується за очищеними значеннями. Сирі значення за межами обрізаються по краю, а виправлені й відкинуті точки позначаються червоним.

### 8. Сторонні бібліотеки графіків для Avalonia
**Проблема.** Бібліотеки графіків додають залежності й мають власні вимоги до версій Avalonia.
**Рішення.** Власний легкий контрол `SignalChart` (рендеринг через `DrawingContext`, ~150 рядків). Розриви в даних показуються розривами лінії.

### 9. Вразлива версія нативної бібліотеки SQLite
**Проблема.** EF Core 10 тягне `SQLitePCLRaw.lib.e_sqlite3` 2.1.11 зі SQLite старішим за 3.50.2 (вразливість CVE-2025-6965, GHSA-2m69-gcr7-jv3q). NuGet-аудит показує попередження NU1903.
**Рішення.** Явно підключили виправлену версію 2.1.12 у `SignalClean.Data.csproj`. Транзитивно вона потрапляє в API і тести.

### 10. Вразлива транзитивна залежність Avalonia
**Проблема.** Avalonia 11.3.0 тягне `Tmds.DBus.Protocol` 0.21.2 з вразливістю CVE-2026-39959 (GHSA-xrw6-gwf8-vvr9): підробка сигналів D-Bus і вичерпання дескрипторів на Linux.
**Рішення.** Явно підключили виправлену версію 0.21.3 у `SignalClean.Client.csproj`.

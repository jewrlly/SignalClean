# Приймальні тест-кейси (C1)

Передумова для всіх кейсів: репозиторій зібрано (`dotnet build`), API запущено (`dotnet run --project src/SignalClean.Api`).
Колонка «Автотест» вказує, який автоматичний тест перевіряє той самий сценарій.

| № | Тест-кейс | Кроки | Очікуваний результат | Автотест | Результат |
|---|---|---|---|---|---|
| TC-01 | Запуск API з нуля | Видалити `signalclean.db`, запустити API, відкрити `http://localhost:5080/health` | `{"status":"ok"}`, файл БД створено | `Health_ReturnsOk` | ☐ |
| TC-02 | Початкові датчики | `GET /api/sensors` | 4 датчики: TEMP-01, HUM-01, PRES-01, CO2-01 | `Sensors_AreSeeded` | ☐ |
| TC-03 | Прийом чистих даних | Запустити симулятор з `--clean` на 30 с, відкрити `/api/sensors/TEMP-01/quality` | Score ≈ 100, клас A | `Ingest_CleanData_AllAccepted_ScoreA` | ☐ |
| TC-04 | Виявлення сплеску та очищення | Надіслати запит із `SignalClean.Api.http` зі сплеском (або запустити симулятор без `--clean`) | Сплеск має статус `Corrected`, CleanValue ≈ медіана, є аномалія `Spike` | `Ingest_DirtyData_DetectsAnomalies_AndCleans` | ☐ |
| TC-05 | Відкидання некоректних значень | Надіслати значення −999 та NaN | Статус `Invalid`, аномалії `OutOfRange` / `NotANumber`, Rejected = 2 | `Ingest_DirtyData_DetectsAnomalies_AndCleans` | ☐ |
| TC-06 | Захист запису ключем | `POST /api/readings` без заголовка `X-Api-Key` | 401 Unauthorized | `Ingest_WithoutApiKey_Returns401` | ☐ |
| TC-07 | Невідомий датчик | Надіслати пакет з кодом `NOPE-99` і з `HUM-01` | `HUM-01` прийнято, `NOPE-99` відхилено з повідомленням | `Ingest_UnknownSensor_IsRejected_OthersAccepted` | ☐ |
| TC-08 | Реєстрація датчика | `POST /api/sensors` з кодом `TEMP-02` | 201 Created; новий датчик є у списку клієнта | `CreateSensor_Valid_Returns201` | ☐ |
| TC-09 | Дашборд показує дані | Запустити API, симулятор, клієнт | Список з 4 датчиків з класами якості; графік оновлюється кожні 2 с; є журнал аномалій | — (ручний) | ☐ |
| TC-10 | Клієнт без API | Зупинити API при відкритому клієнті | Клієнт не падає; у статусі «API недоступний»; після запуску API дані повертаються | — (ручний) | ☐ |
| TC-11 | Мультиплатформність | Виконати TC-01…TC-10 на Windows і на Linux (або macOS) | Однакова поведінка на обох ОС | CI-матриця ubuntu/windows/macos | ☐ |

## Шаблон опису кейсу для звіту

**Тест-кейс TC-04: виявлення сплеску та очищення**
- **Опис:** сплеск на тлі стабільного сигналу має бути виправлений, а не збережений як є.
- **Кроки для відтворення:** 1) запустити API; 2) запустити симулятор `--seed 42`; 3) у клієнті обрати TEMP-01.
- **Результат:** *(скріншот графіка: червона точка на сірій лінії, синя лінія без сплеску; скріншот журналу аномалій)*
